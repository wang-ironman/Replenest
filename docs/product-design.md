# 家有余量：首版产品设计

## 产品要解决什么

用户不需要每天维护一份精确仓库账本，而需要在恰当的时候知道：家里的常用品大概还够用多久，这次应该补什么。

“无库存”在这里指减少不必要囤积，不是库存清零。提醒要覆盖配送时间和安全余量，用品重要程度不同，允许分别设置提前天数。

首版定位：中国大陆、个人或单家庭、Android、离线优先、无账号。首次登记从最常用的 3–5 项开始，不要求全屋盘点。优先考虑规格明确、用量较规律、愿意固定品牌复购的用品。家庭成员数、洗衣次数等习惯可以通过 AI 转换为待确认用量；规则端最终保存可解释的数量和日消耗量。

## 关键产品取舍

| 问题 | 首版决定 | 原因 |
| --- | --- | --- |
| 首页展示什么 | 将近用完的用品、预计剩余天数和数量 | 用户来判断下一次采购；不放装饰性说明卡片 |
| 需要天天打卡吗 | 不需要；补货和偶尔修正余量 | 降低记账负担 |
| 预测如何起步 | 现有份数 + 一份能用几天，规格选填 | 不填容量、重量也可预测；已知规格时自动计算总量 |
| 滤芯如何处理 | 独立周期模式，按剩余天数，更换后重置 | 滤芯的更换不等于数量消耗 |
| 是否自动增加库存 | 只有用户确认到货或已更换 | 下单和实际到货不同 |
| 比价是否可靠 | 先做同规格渠道搜索，不显示实时价格 | 尚未接入交易、价格与库存数据 |
| 是否依赖大模型 | 默认规则，可选 AI 辅助录入 | 离线预测与通知不受服务不可用影响 |
| 是否收费 | 首版验证需求，暂不实现订阅和支付 | 先验证持续使用价值 |

## 当前已实现的操作闭环

1. 从咖啡胶囊、洗衣液、垃圾袋、卫生纸、猫粮、滤芯或自定义模板登记。
2. 模板自动带出数量单位，自定义默认“份”，单位使用下拉选择。用户主要调整现有数量、使用周期和提前提醒天数，数字提供加减、常用值与滑动选择；也可手动输入有效数字。商品规格默认收起且选填，模板规格会保留，展开后可修改或清除。
3. 首页根据实际登记时间，按日计算余量与预计用完日期。
4. 达到提醒日期后自动出现在采购清单，也可以手动提前加入。
5. 选择渠道搜索相同规格；自行核对商家、实际规格、价格、运费和配送时间。
6. 标记已下单后，保留待到货状态并停止重复通知，不增加家中余量。
7. 到货时输入新增包装数，原有余量加上新到货数量；周期用品确认已更换后重置。
8. 若估算不准，修正实际余量。记录跨度足够时，温和校准未来用量。

提供暂停补货提醒、通知延后 3 天、删除用品、最近操作记录、分享采购清单、本地 JSON 备份恢复。

## 可解释的预测规则

### 数量型用品

日用量 = 每包装数量 ÷ 每包装预计使用天数。

登记总量 = 每份规格 × 现有数量。例：计量单位“毫升”、数量单位“瓶”、每份规格 2000、现有数量 2，自动登记 4000 毫升。数量支持小数，补货和实际余量修正同样按瓶、包、卷等数量填写。卡片显示预计份数及折算总量；旧记录保留原来的基础计量总量，增加数量单位时不会再次乘算。

规格未填写时，内部按每份规格 1、计量单位等于数量单位计算。例如 2瓶、每瓶60天，预计120天；无需额外填写毫升。旧记录的规格不会因为界面收起而丢失。

数字输入校验整个编辑结果：字母、汉字、科学计数法、重复小数点和负号会被拒绝，不会把“2abc”悄悄转成2。临时空值或小数点允许编辑，但保存时必须为合法数字；提醒提前天数为整数。每份使用天数和周期输入最多36500天，提醒提前天数最多3650天；最终仍执行用品总量与预测范围校验。

预计余量 = max(0，登记总量 − 日用量 × 已过自然日数)。

预计用完日期 = 余量登记日期 + ceil(登记总量 ÷ 日用量)。

提醒日期 = 预计用完日期 − 提前天数。

例如 30 粒胶囊一盒，预计一盒用 15 天，则每天约 2 粒。登记有 24 粒，预计还可用 12 天；提前 3 天提醒，就在约 9 天后进入补货期。按自然日粗估，不给出伪精确的小时。

补货时：新总量 = 当前预计余量 + 新增包装数 × 每包装数量。缺货期间不累积“负库存”。

修正时：间隔至少 3 天且观察到实际消耗，观察日用量 = (上次登记总量 − 本次实际余量) ÷ 间隔天数；新日用量 = 旧日用量 × 70% + 观察日用量 × 30%。较短间隔或数量增加不更新日用量。每次修正重置余量基准日期。这个加权规则是首版设计选择，尚未用真实家庭长期样本验证。

### 周期型用品

用户填写更换周期天数和当前剩余天数，倒计时不受“包装数”影响。确认更换后，从当天重新开始完整周期。提醒只是用户登记周期的管理，不代表滤芯性能、水质或安全检测。

### 尚未覆盖

不区分已拆封与未拆封批次，不处理保质期、多人并发编辑、旅行自动停用、季节变化或无操作时的主动学习；暂停选项暂停补货提醒，余量仍随时间递减。需要长期停用时，恢复后应修正实际余量。

## 可选 AI：降低输入负担

入口在登记流程，不做全屋后台分析。用户配置 API、获取并搜索模型列表、选择文本模型，点击“开启 AI”后才可主动发起建议请求。设置页与 API 配置页均提供“开启 AI / 关闭 AI”按钮，立即保存状态；关闭保留配置。底部“保存配置”不会隐式开启 AI，已有配置但未开启时可在录入入口选择“开启并继续”。

发送内容只有本次用户输入及通用结构化提示词，不附带整份库存、操作历史或购物信息。服务返回用品、单位、每包装数量、当前余量、预计周期、提前天数和解释；信息不足时先追问。应用校验数值并展示建议，用户进入可编辑表单确认保存。无效响应、鉴权失败、超时或网络失败时可以继续手动登记。

默认使用兼容 OpenAI 的 `POST /chat/completions`。模型列表通常为 `GET /models`，允许配置独立列表 URL，支持搜索选择和手工模型 ID。平台预设仅提供地址起点，模型名由接口实际返回；没有绑定固定型号。

| 平台 | 配置方式 |
| --- | --- |
| DeepSeek、硅基流动、Kimi / Moonshot、智谱、OpenAI、Gemini、豆包 / 火山方舟 | 提供常用兼容 API 地址预设，用户核对自己账号的地址与权限 |
| 阿里云百炼 | 根据地域、业务空间填写对话地址及独立模型列表地址；适配 `output.models` 与分页 |
| 其他平台或代理 | 自定义 HTTPS OpenAI 兼容地址，可覆盖模型列表 URL |

原生 Anthropic Messages、原生 Gemini 等协议尚未单独适配；Gemini 使用官方 OpenAI 兼容入口，Claude 可通过兼容网关接入。模型列表里可能含语音、图片、向量等型号，用户需选择支持文本对话的模型。获得模型名单不等于该模型推理已验证。

密钥使用 Android Keystore 的 AES/GCM 加密保存在本机；应用禁用系统自动备份，用户导出仅包含用品记录。更换对话地址要求重新填写密钥，禁跟随 HTTP 重定向，避免把旧密钥带到新服务。使用 AI 的网络请求可能产生服务商费用，应用本身不代理计费。

## 本地提醒与数据

通知默认关闭，由用户主动开启并授予系统权限。每天上午 9 点附近汇总到期用品，只要没有到期项就不发提醒；已下单、暂停、通知延后期内的用品跳过。无需精确闹钟权限。重启设备、时间或时区变化、应用更新后重建计划。

Android 省电机制可能延迟通知，强制停止后需重新打开应用。设备内存中的页面在重新进入应用时刷新；预测以设备本地日期为准。应用没有后台服务器，不采集行为分析，不上传家庭备份。

数据仅存在本机，卸载会删除；提供用户自选位置的 JSON 导出与恢复，恢复先验证并确认替换。首版保留最近 100 条操作，每户最多 500 项用品。API 配置不随备份导出。

## 下一步验证什么

建议先邀请少量家庭连续试用 2–4 周，每户只登记 3–5 项；这是待执行的实验，并非已完成验证。重点观察：用户能否快速登记首项；一周后是否仍愿意确认补货；预测与真实用完日期相差多少；漏提醒是否导致临时采购；提醒是否过早引发囤积。

若需要频繁改数字却没有节省心力，应先降低维护成本，不急着增加 AI 对话或商品推荐。验证留存后再讨论家庭共享、条码/包装识别、订单导入和真实规格单价比较。订阅可以围绕多人协同、跨设备备份和长期用量趋势测试，但不能把“有大模型”本身当成付费价值。
